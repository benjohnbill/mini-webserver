# impl-core 완료 보고

## 변경 파일

- `include/route.h`, `src/route.c`에 `=@path` 파싱, 라우트 교체 API, 백엔드 및 테이블 참조 카운트, `route_live`를 추가했습니다.
- `include/server.h`, `src/config.c`에서 성공 시 초기 테이블의 소유권을 `live`에 넘기고, 인자 파싱이 도중에 실패하면 이미 생성한 백엔드를 정리합니다.
- `src/server.c`, `src/health.c`에서 워커 요청, 헬스 체크 한 바퀴, 상태 표 렌더링이 각각 테이블 참조를 유지합니다. 메인 스레드가 SIGHUP을 받아 새 테이블을 교체하고 `reload: ok` 또는 `reload: failed: <이유>`를 기록합니다.

## 설계와 정적 확인

- 파일 경로는 시작할 때 `realpath()`로 정규화합니다. 같은 route에서 host와 port 문자열이 같은 멤버는 기존 백엔드 객체를 공유합니다. 가중치와 링은 테이블마다 따로 보관합니다.
- 모든 파일의 검증이 끝난 뒤에만 현재 테이블을 교체합니다. 잘못된 토큰이나 중복을 비롯한 오류가 발생하면 교체 후보 전체의 참조를 정리합니다. FIFO로 바뀐 파일이 메인 스레드를 막지 않도록 일반 파일만 읽습니다. NUL이 포함된 텍스트도 거부합니다.
- 현재 테이블 포인터를 읽고 참조를 올리는 구간과 테이블 교체 구간에 같은 mutex를 사용합니다. 네트워크 I/O와 파일 파싱은 해당 mutex 밖에서 실행합니다. 상태 표 버퍼 부족, 인자 파싱 실패, 서버 시작 실패, 정상 종료 경로의 참조 정리를 확인했습니다.
- `git diff --check`를 통과했습니다. 컨테이너 빌드 시 첫 환경 확인에서 `docker: command not found`가 나왔고, 이후 조율자 지시에 따라 실행을 중단했습니다. 빌드 경고, HUP 동작, ASan 검증은 impl-tools 결과가 필요합니다.
- 테스트에서 `config_parse_args()`가 성공한 뒤 같은 `cfg`를 재사용하기 전에는 `route_live_destroy(&cfg.live)`가 필요합니다. `cfg.routes`를 직접 초기화하는 상태 표 테스트에는 `route_live_init(&cfg.live, &cfg.routes)`와 `route_live_destroy(&cfg.live)`가 필요합니다.

## 수정 2차

- `src/route.c`, `src/server.c`에서 파일을 읽거나 파싱할 때 실패하면 `reload: failed: <절대 경로>: <이유>`를 기록합니다. 경로의 개행 문자는 공백으로 바꿔 로그를 한 줄로 유지합니다.
- `src/route.c`에서 포트를 기존 범위로 검증한 뒤 선행 0 없는 10진 문자열로 저장합니다. `:08001`과 `:8001`은 같은 호스트에서 중복으로 판정되고, 재로딩 시 표기만 바꾸면 기존 백엔드 객체를 재사용합니다.
- 공통 파서에서 중복 검사와 재사용으로 이어지는 경로 및 로그 버퍼 크기를 정적으로 확인했습니다. `git diff --check -- src include`를 통과했습니다. Docker 빌드와 실행 테스트는 조율자 지시에 따라 실행하지 않았습니다.

## 수정 3차

- `src/main.c`의 첫 동작으로 `SIGHUP`을 무시하도록 설정했습니다. 인자 파싱 뒤 `server_run()`이 기존 핸들러를 설치합니다.
- `src/route.c`의 재사용 판정에 주석을 추가했습니다. 제거 직후 같은 주소를 다시 넣으면 이전 요청이 살아 있는 동안 두 객체의 `inflight`가 분리됩니다.
- 시그널 설정 순서와 변경 범위를 정적으로 확인했습니다. Docker 빌드와 실행 테스트는 지시에 따라 실행하지 않았습니다.

## 수정 4차

- `src/main.c`에서 인자 파싱 전에 `SIGHUP`을 블록합니다. `src/server.c`에서 핸들러를 설치하고 워커와 헬스 스레드를 생성한 뒤, 메인 스레드의 마스크에서만 `SIGHUP`을 해제합니다. 대기 중인 `SIGHUP`은 첫 accept 루프의 재로딩 검사로 이어집니다.
- 핸들러 설치와 스레드 생성, 시그널 마스크 복원 순서를 정적으로 확인했습니다. `git diff --check`를 통과했습니다. Docker 빌드와 실행 테스트는 지시에 따라 실행하지 않았습니다.
